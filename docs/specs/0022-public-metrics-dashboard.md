# SPEC-0022：公开装机统计看板

- 状态：in-progress
- 日期：2026-11-15
- 关联：SPEC-0018 · SPEC-0016 · ADR-0023 · ADR-0029 · 代码 `server/metrics/`

## 背景 / 问题

装机统计端点已经能通过 `GET /api/report` 返回 M1～M8，但查询需要手工携带
`MAINTENANCE_TOKEN` 并拼装 URL，日常查看趋势不方便。项目作者希望提供一个前端看板，
并把聚合统计公开；看板不需要登录，也不允许在前端暴露维护令牌。

`site/` 是面向用户的纯静态宣传页，当前明确禁止 `<script>`、无构建依赖，且由 GitHub Pages
独立发布。把需要请求统计 API 的看板塞进 `site/` 会引入跨域、脚本约束与职责混杂。
统计服务和看板改放在同一个 `metrics` 域名下可以保持同源，并让宣传页继续只承担产品介绍。

现有 `/api/report` 允许任意 366 天范围并支持 CSV，每次查询会读取大量 KV sketch。
如果直接把该接口公开，匿名访问者可任意组合查询参数并绕过页面频繁触发高成本读取。
因此公开访问需要固定范围和短期缓存，维护者接口保持原样。

## 需求（做什么）

1. 在统计服务域名下提供公开看板 `https://metrics.hunhun.qd.je/dashboard/`；
   `site/` 宣传页、`master` 发版产物和桌面应用均不链接或嵌入看板。
2. 看板公开可访问，不要求账号、登录、Cookie、维护令牌或 `Authorization` 请求头；
   报表聚合数据同样公开。
3. 新增公开只读接口 `GET /api/public-report`，只服务看板：
   - `range` 只允许 `7d`、`30d`、`90d`，默认 `30d`；
   - `granularity` 只允许 `day`、`month`，默认 `day`；
   - 不接受任意 `from` / `to`、`format=csv`、重复参数或未知参数。
4. 日粒度响应输出当前固定范围逐日的 M1、M3、M5，以及历史 M7、M8；
   月粒度响应按自然月合并输出 M2、M4、M6，以及历史 M7、M8。
   两种响应都包含 `approximate=true`、`method=hll`、`consistency=eventual_60s`、
   `range`、`granularity`、`from`、`to`、`generatedDay` 和 `metrics`。
   响应另含 `summary.active`、`summary.newInstalls` 与 `summary.versionsActive`：
   前两者分别合并范围内每日 HLL，`versionsActive` 按版本合并范围内每日版本 HLL；
   三者用于看板概览，不是把日值相加，也不是新增的上报指标。
5. `/api/public-report` 只返回匿名聚合、版本分布和统计元数据；不得返回逐装机记录、
   明文 `installId`、IP、请求头、原始事件、服务端异常或环境变量。
6. 现有 `GET /api/report` 保持维护令牌鉴权、任意日期范围和 JSON/CSV 能力；
   看板前端不读取、不发送也不提示任何维护令牌。
7. `/api/public-report` 与看板同源，不新增 CORS；成功响应缓存 60 秒，
   允许浏览器和 EdgeOne 边缘缓存复用，错误响应不使用公开缓存。
8. 看板提供以下视图：
   - 最近 7 / 30 / 90 天分段选择，默认最近 30 天；
   - 日 / 月粒度切换，默认按日；
   - 累计装机 M7、当前范围活跃、当前范围新增、版本数量；
   - 活跃装机趋势、新增装机趋势；
   - 各版本累计装机 M8 和当前范围版本活跃 M3/M4；
   - 当前范围的可访问明细表；
   - 数据更新时间、加载失败重试和空数据状态。
9. 页面文案必须明确：
   - 统计单位是“装机”，不是“用户”；
   - HLL 为近似估计，存在约 1～3% 相对误差；
   - KV 数据最终一致，最多延迟约 60 秒；公开响应还会复用最多 60 秒缓存，
     因此页面数据相对采集时间可能累计延迟约 2 分钟；
   - 无法统计卸载，不能把累计装机解释为现存用户数；
   - 同一装机升级后可能出现在多个版本的活跃数据中。
10. 看板只使用同源的本地 HTML、CSS、JavaScript 和图形资源，不加载第三方脚本、统计 SDK、
    远程字体、CDN、图片或 iframe。
11. 看板页面和静态资源启用严格 CSP、`Referrer-Policy: no-referrer`、
    `X-Content-Type-Options: nosniff`、禁止 iframe 嵌入和最小化浏览器权限；
    HTML、JavaScript、CSS、接口请求和测试中不得出现维护令牌。
12. 变更只落在 `server/metrics/` 与 `docs/`；不修改桌面应用、`site/`、GitHub Pages
    发布流程或客户端上报行为。

- [x] **D9** 加载中、空数据、接口失败与重试状态均可判定；失败后保留当前范围并显示通用错误，

## 非目标 / 边界

- 不公开任意 366 天范围、CSV 导出、原始 KV sketch 或逐装机明细。
- 不新增账号、登录、Cookie 会话、权限角色或管理员操作界面。
- 不做低于 60 秒刷新周期或 WebSocket 实时看板。
- 不增加留存、漏斗、语言/OS/安装形态分布、下载量入库等 SPEC-0018 之外的新指标。
- 不修改客户端上报协议、上报开关、HLL 存储结构或历史数据。
- 不修改 `site/` 宣传页、GitHub Pages workflow 或桌面应用。
- 不提供公开数据徽章、嵌入式 widget 或第三方 API 集成。

## 设计要点（可选）

- 看板作为 `server/metrics/public/dashboard/` 下的静态文件随 EdgeOne 统计项目发布；
  与 API 同源，避免 CORS，也不扩大 GitHub Pages 的脚本和发布面。
- 公开路由作为 `/api/report` 之外的独立入口。底层可复用日期、KV 读取、HLL 合并和 JSON
  序列化函数，但公开路由必须自己限定固定范围和输出白名单，不能把 `format` 等维护者参数透传。
- 公开路由不读取 `MAINTENANCE_TOKEN`；前端只请求 `/api/public-report`，不接受用户输入令牌。
- 固定范围让响应 URL 可稳定缓存；缓存时长与 `consistency=eventual_60s` 保持一致。
  EdgeOne 当前全局 `Cache-Control: no-store` 需要在实现时收窄到不缓存的路由，不能覆盖
  公开报表的 60 秒缓存。页面文案必须区分 KV 一致性延迟与响应缓存，不把总延迟宣传为 60 秒。
- 页面采用信息密度较高、可扫描的运维看板布局：范围与粒度控制在上方，概览指标随后，
  趋势、版本和明细按桌面双列、移动端单列排列。图表使用本地实现的轻量 SVG/CSS，
  不引入运行时依赖。
- 图表和表格共用一次公开接口响应；切换范围或粒度只发起一个请求。刷新按钮重新读取缓存窗口内
  的最新可用快照。
- 版本活跃、版本累计和趋势使用不同数据维度；页面不将各版本活跃相加展示为总活跃。
- 安全头由 EdgeOne 路由或静态响应统一设置，页面不依赖 `<meta>` 提供 CSP。
- 错误处理对用户显示通用文案；服务端状态码保留 `400`、`405`、`503` 语义，
  日志不得记录令牌或完整请求头。
