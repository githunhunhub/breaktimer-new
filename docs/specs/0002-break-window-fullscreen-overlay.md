# SPEC-0002：休息窗口全屏遮挡（软遮挡，允许手动结束）

- 状态：in-progress
- 实现状态：阶段 2 代码与自动化验证完成；Windows 人工验收通过，macOS/Linux 平台验收待做
- 日期：2026-10-13
- 关联：ADR-0002 · ADR-0004 · 旧实现 `breaktimer-app/app/main/lib/windows.ts`、`ipc.ts`、`breaks.ts` 与 `renderer/components/break.tsx`

## 背景 / 问题

旧版 BreakTimer 的 Popup 模式会在每个显示器上弹出一个休息窗口；休息阶段若开启「Backdrop」，
会用无边框、透明、置顶的窗口铺满该显示器，用半透明背景限制分心。这是产品核心体验，重构后不能丢。

读旧源码后确认其语义是 **soft overlay（软遮挡）**：不抢焦点、不锁键盘鼠标、不阻止切换任务，
且用户可随时点「结束休息」。本 spec 固化这一真实行为。

## 需求（做什么）

1. 休息触发（Popup 模式）时，在**每个显示器**上各显示一个休息窗口。
2. 窗口为无边框、透明、置顶、跨工作区可见、不进任务栏、**不抢焦点**的软遮挡窗口。
3. 休息阶段：
   - 当 `showBackdrop=true` 时，窗口**铺满所在显示器**（原生全屏或等价），背景按 `backdropOpacity` 半透明遮挡。
   - 当 `showBackdrop=false` 时，窗口**居中约 500×300**，不铺满。
4. 窗口内容包含休息标题、文案、进度/倒计时，以及**「结束休息」按钮（允许手动结束）**。
5. 依设置展示「推迟 / 跳过」按钮（行为与旧版一致，见验收标准）。
6. 手动结束与倒计时自然结束走同一条「结束休息」流程：关闭所有显示器的休息窗，交由调度层记录并安排下一次休息。

## 验收标准（可测）

- [x] 单显示器与多显示器环境下，休息触发时每个显示器都出现一个置顶、无边框、无任务栏图标的休息窗。
- [x] `showBackdrop=true` 时，休息阶段窗口铺满所在显示器，背景为半透明遮挡色（受 `backdropOpacity` 控制）。
- [ ] `showBackdrop=false` 时，休息阶段窗口居中且约 500×300，不铺满。
- [x] 触发休息后，用户当前活跃应用仍保持焦点，可继续输入/点击（验证软遮挡：不抢焦点）。
- [x] 点击「结束休息」后，所有显示器的休息窗关闭，并进入「结束休息」流程（不残留窗口）。
- [ ] 启用推迟时，点「推迟」按推迟时长重新调度；启用跳过时，点「跳过」按正常频率重新调度（与旧版一致）。
- [x] 多显示器下，主窗口发起的结束/进度同步能广播到其它显示器窗口（各窗进度一致）。
- [ ] macOS 上不抢焦点（`setFocusable(false)` 在 `show()` 前生效）；Linux 上置顶/跨工作区在受支持的窗口管理器下生效，并记录已知限制。

## 非目标 / 边界

- 不实现**硬锁定**：独占键盘鼠标、禁止 Alt+Tab/切任务（见 ADR-0002）。
- 本 spec 不覆盖：休息调度算法、工作时段、闲置重置、系统托盘、自启动、`Notification` 通知模式、声音（留待后续 spec）。
- 不覆盖「本次休息是否计为完成」（≥ 一半时长）的统计逻辑，该逻辑属于调度/统计 spec；本 spec 只保证窗口正确展示与结束流转。
- 暂不做多语言本地化。

## 设计要点（可选）

- 每显示器一个 `WebviewWindow`，组合 `decorations:false` + `transparent:true` + `alwaysOnTop` + `skipTaskbar` + `visibleOnAllWorkspaces` + `focusable:false`。
- 休息阶段铺满用「窗口位置与尺寸 = 显示器 bounds」实现软遮挡（ADR-0004），不调用原生全屏；无遮挡时 `setSize(500,300)` 并居中。
- 后端广播 `break-status`，并统一关闭所有休息窗（对应旧版 `sendIpc(BreakEnd)` 的语义）。
- 前端复用旧 `break.tsx` 及其子组件，只把 `ipcRenderer` 调用替换为 Tauri `invoke`。
