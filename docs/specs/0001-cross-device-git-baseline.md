## 背景 / 问题

项目会在两台电脑上交替开发。如果文档、配置、AI 记忆或子模块只存在某一台机器上，
切换设备后就会丢失上下文、产生环境差异，甚至无法复现同一份开发状态。

## 需求（做什么）

1. 所有可移植、可复现、对项目有意义的内容必须纳入 Git：文档、AI 记忆与会话、源代码、
   测试、构建配置、依赖锁文件、共享编辑器配置、脚本与资源。
2. 不具备可移植性或不应公开的内容明确排除，并保持可恢复：密钥、机器本地路径与个人 IDE 状态、
   本地环境变量、依赖目录、构建产物、缓存与日志。
3. 旧源码继续以 Git submodule 固定提交引用；新设备可用一条命令初始化。
4. 文本换行与编码由仓库配置统一，不依赖各机器不同的 Git 或编辑器设置。
5. 文档给出新设备从干净克隆恢复到可开发状态的步骤。

## 非目标 / 边界

- 不纳入密钥、令牌、证书私钥或本地环境变量。
- 不纳入 `node_modules/`、构建产物、缓存、日志等可再生内容。
- 不改变 `breaktimer-app/` submodule 的上游地址与固定提交。
- 不要求把每台机器特有的绝对路径或 IDE 个人状态入库。

## 设计要点（可选）

- 默认原则：仅凭仓库内容即可复现的，纳入 Git；只对某台机器有意义或无法安全公开的，排除并记录恢复方式。
- `.editorconfig` 负责编辑器行为，`.gitattributes` 负责 Git 入库与检出行为，两者共同消除跨平台文本差异。
- submodule 固定提交保证旧源码在所有设备上指向同一版本。
