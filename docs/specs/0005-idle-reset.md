# SPEC-0005：闲置重置

- 状态：done

## 背景 / 问题

用户离开电脑时不应继续累计休息倒计时，否则回到电脑会立刻触发一次「迟到」的休息。旧版通过系统空闲状态检测，把离开视为自动重置。

## 需求（做什么）

1. 支持全局开关 `idleResetEnabled` 与时长 `idleResetLengthSeconds`。
2. 检测到系统空闲（idle）达到时长后，重置休息倒计时，并把空闲起点回推到「时长前」。
3. 支持 `idleResetNotification`：空闲重置时可选发一条系统通知说明已自动检测到休息。
4. 正确处理「锁屏」（locked）状态，避免锁屏与闲置逻辑互相干扰。

## 验收标准（可测）

- [x] 用户空闲达到 `idleResetLengthSeconds` 后，休息倒计时被重置（不再补发）。
- [x] 关闭 `idleResetEnabled` 时不因空闲重置。
- [x] 开启 `idleResetNotification` 时，空闲重置会发系统通知；关闭则不发。
- [x] 锁屏场景按旧版语义处理，不产生错误的重置或补发。

## 非目标 / 边界

- 不做基于摄像头/面部识别的「是否在屏幕前」检测。
- 系统空闲检测依赖操作系统能力，跨平台差异在实现时记录。

## 设计要点（可选）

- 后端通过系统空闲状态（active/idle/locked）驱动，对应旧版 `powerMonitor.getSystemIdleState`。
- 空闲重置与工作时段、休眠恢复在同一循环内协调（见 SPEC-0003）。
