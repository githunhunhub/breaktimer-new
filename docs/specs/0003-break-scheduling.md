## 背景 / 问题

BreakTimer 的核心是一个后台循环：按频率安排休息、支持推迟/跳过、记录休息是否完成、处理休眠/锁屏恢复，并在启用状态变化时维护「距上次休息」的计时。这部分逻辑是产品的心脏。

## 需求（做什么）

1. 后台以固定周期（旧版 1s）驱动调度循环。
2. 当满足「已启用、在工作时段、未闲置」且到达 `breakFrequencySeconds` 时触发休息（Popup 或 Notification，见对应 spec）。
3. 支持 `postponeLengthSeconds`（推迟）与 `postponeLimit`（最多推迟次数）；跳过按正常频率重新调度。
4. 支持「立即开始休息」（设置项 `immediatelyStartBreaks` 或托盘触发），跳过倒计时。
5. 结束休息时按实际时长判定：达到 `breakLengthSeconds` 的一半及以上记为「完成」并重置「距上次休息」，否则不计（保留旧语义）。
6. 启用/禁用休息：从禁用切换到启用时，重置「距上次休息」。
7. 处理系统休眠/锁屏：设备长时间无响应时避免补发已过期的休息。

## 验收标准（可测）

- [x] 到达 `breakFrequencySeconds` 且满足触发条件时，触发一次休息（并调度下一次）。
- [x] 推迟后按 `postponeLengthSeconds` 重新调度；跳过按 `breakFrequencySeconds` 重新调度。
- [x] 达到 `postponeLimit` 后不再允许推迟（`getAllowPostpone` 返回 false）。
- [x] 「立即开始休息」直接进入休息，不做倒计时。
- [x] 结束休息时，实际时长 ≥ 一半记为完成并更新「距上次休息」；不足一半不计。
- [x] 从禁用切换到启用时，「距上次休息」重置。
- [x] 系统休眠/锁屏超过 `breakFrequencySeconds` 时，跳过并重置调度，不补发休息。

## 非目标 / 边界

- 不覆盖休息窗口的呈现（见 SPEC-0002）与通知呈现（见 SPEC-0008）。
- 不覆盖工作时段判定（见 SPEC-0004）与闲置判定（见 SPEC-0005），本 spec 只消费其结果。
- 不做云端同步或团队级调度。

## 设计要点（可选）

- 状态机集中于 Rust 后端，前端只触发动作（开始/结束/推迟/跳过）并读取进度。
- 「距上次休息」「下次休息时间」「是否进行中」作为后端状态，通过 command 暴露给前端与托盘。
