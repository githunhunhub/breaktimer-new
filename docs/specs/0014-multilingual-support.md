# SPEC-0014：多语言支持

- 状态：done
- 日期：2026-10-22（更新 2026-10-23）
- 关联：ADR-0012 · PLAN-0003 · SPEC-0002 · SPEC-0006 · SPEC-0008 · SPEC-0010

## 背景 / 问题

当前应用面向用户的文案全部硬编码为英文，设置页、休息页、托盘、About 和系统通知分别由
React 与 Rust 生成。用户需要中文界面，同时希望后续新增语言时只添加翻译资源，不再修改
各页面的文案和语言注册代码。

## 需求（做什么）

1. 首版支持 `en-US`（英语）和 `zh-CN`（简体中文）；`en-US` 是资源基准语言和最终回退语言。
2. 默认跟随系统语言。用户可在设置窗口的 `System` 页签中手动选择语言；语言选择位于
   `Start at login` 卡片上方。
3. 设置字段为 `language: string | null`，`null` 表示跟随系统。旧设置缺少该字段时按
   `null` 加载，不要求用户重新保存。
4. 手动选择的语言在点击设置页 `Save` 后持久化并立即生效；未保存的草稿不影响当前界面。
   保存后当前设置页、已存在的休息页与托盘立即切换语言；系统通知从下一次触发开始使用新语言。
5. 系统语言在应用启动时解析；Windows 运行期间修改系统语言后，重启应用生效。系统语言
   不受支持时使用 `en-US`。
6. 翻译资源统一放在 `app/locales/`。每种语言一个 JSON 文件，包含 locale 元数据与
   messages；React 与 Rust 读取同一份资源，不维护两套翻译。
7. 新增一种受支持的语言时，只增加一个合法翻译文件并重新构建，语言列表自动出现该语言，
   无需在页面或后端语言枚举中单独注册。
8. 翻译覆盖全部用户可见文案：设置页、休息页、托盘菜单与状态文本、About、系统通知、
   ARIA 标签和屏幕阅读器文案。
9. 消息支持 `{name}` 占位符与 `one` / `other` 简单复数；`count === 1` 使用 `one`，
   其余情况使用 `other`。
10. 当前语言缺失翻译键时回退到 `en-US` 的同一 key；非基准语言资源损坏或 locale 不受支持时
    按 `en-US` 处理，不得阻止应用启动。`en-US` 资源的 schema 与 key 完整性由自动化测试保证。
11. `breakTitle` 与 `breakMessage` 仍由用户设置。值等于旧版内置英文默认值时，按当前语言
    显示内置翻译；其他值视为用户自定义内容，原样显示，不翻译。Notification 模式的
    通知标题使用 `breakTitle`，正文使用 `breakMessage`，并执行相同的默认值识别。
12. 产品名 `BreakTimer-new`、版本号、代码链接、许可证标识、语言选择中的原生语言名和底层
    技术错误详情保持原样；技术错误详情可继续使用英文。

## 非目标 / 边界

- 不引入完整 ICU MessageFormat 或 ICU4X/CLDR 数据；本期不处理日期、时间、数字、货币、
  ordinal、select、rich text 等高级格式。
- 不提供运行时语言包导入、在线翻译、翻译编辑器或热更新；新增语言随应用构建发布。
- 不实现从右到左（RTL）布局。未来若支持 RTL 或现有轻量格式无法表达的语言，另立需求评估。
- 不自动翻译用户输入的休息标题、休息消息或其他自由文本。
- 不本地化安装包、发布脚本和仓库文档；范围仅限应用运行时界面与系统通知。
- macOS/Linux 的平台差异不在本次验收范围。

## 设计要点（可选）

- `app/locales/en-US.json` 与 `app/locales/zh-CN.json` 是唯一翻译源。文件形如：

  ```json
  {
    "locale": "zh-CN",
    "name": "简体中文",
    "aliases": ["zh", "zh-Hans", "zh-Hans-CN"],
    "messages": {
      "settings": {
        "save": "保存"
      }
    }
  }
  ```

- React 使用轻量 `I18nProvider`、`useI18n()` 与 `t()`，通过 `import.meta.glob` 自动发现资源；
  Rust 使用对应 i18n 模块，通过 `include_dir` 嵌入同一目录。
- 当前生效 locale 由 Rust 统一解析系统语言与无效设置；前端通过 IPC 获取它。保存语言后发出
  `locale-changed` 事件，各 WebView 重新渲染，Rust 刷新托盘快照。
- 托盘仍沿用稳定根菜单原地更新（ADR-0010）；快照比较必须包含有效 locale 或最终菜单文案，
  确保语言变化能更新文本而不重建菜单。
- 默认休息标题与消息通过“是否精确等于旧内置英文默认值”判断；精确输入相同英文的用户内容
  也会按内置文案处理，这是已接受的边界。
