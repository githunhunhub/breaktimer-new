# SPEC-0026：公开报表定时预聚合快照（暂缓实现）

- 状态：draft
- 日期：2026-11-16
- 关联：SPEC-0018 · SPEC-0022 · SPEC-0025 · ADR-0023 · ADR-0032

## 背景 / 问题

SPEC-0025 已把公开报表从“按理论分片盲读”改为“列举实际存在的 key 后读取”，并增加
60 秒 Cache API。数据稀疏时，这项优化已能把公开请求的 KV 扇出降到较小范围。

但公开接口只有六种固定响应：`7d/30d/90d` 与 `day/month` 的组合。随着每天产生数据的
分片逐渐增多，动态计算仍会逼近原始的理论读取量：

```text
7d  = 7  × 48 + 32 =  368 个 get，另有最多  23 个 list
30d = 30 × 48 + 32 = 1472 个 get，另有最多  92 个 list
90d = 90 × 48 + 32 = 4352 个 get，另有最多 272 个 list
```

同一份聚合结果会被所有看板访问者反复计算。若未来数据密度、访问量或冷缓存请求增加，
KV 读取成本和首字节延迟会再次上升。相比继续优化每次动态读取，更合适的后续方案是由
定时任务预先生成六份公开响应快照，让公开请求通常只读取一个快照 key。

本 SPEC 只记录候选方案。当前暂缓实现，不代表已确认排期；是否实施要等重新评估触发条件
满足并另行确认。

## 需求（做什么）

若未来决定实施，需满足以下需求：

1. 预生成六种固定公开响应，每个组合对应一个稳定快照 key：

   ```text
   r_public_v1_7d_day
   r_public_v1_7d_month
   r_public_v1_30d_day
   r_public_v1_30d_month
   r_public_v1_90d_day
   r_public_v1_90d_month
   ```

   快照 key 不使用 `h_` 前缀，避免混入现有 HLL 指标 key 的探测与列举范围。
2. 每个快照保存完整包装，至少包含 `schemaVersion`、`generatedAt`、`range`、
   `granularity` 和可直接返回的最终报表 `payload`。`payload` 必须复用现有公开报表的
   聚合与序列化语义，不保存原始 HLL 草图或逐装机数据。
3. 每 5～10 分钟刷新全部六份快照；首次实施建议 10 分钟，先控制刷新成本。刷新时间与
   KV 最终一致窗口、公开缓存窗口一起计入数据新鲜度。
4. 提供仅维护者/定时任务可调用的刷新入口，例如：

   ```text
   POST /api/refresh-public-snapshot?range=7d&granularity=day
   Authorization: Bearer <SNAPSHOT_REFRESH_TOKEN>
   ```

   入口只接受六种固定组合和 `POST`；令牌从 EdgeOne 环境变量与定时任务密钥读取，
   不进入前端、URL、日志或仓库。
5. 每次刷新请求只生成一个快照，六次调用由定时任务编排。调用应串行或限制并发，
   避免一次函数请求同时合并多个 90 天报表，也避免刷新任务重叠。
6. 当前技能包未提供可直接落地的原生定时配置。实施前先复核 EdgeOne 控制台/CLI 是否
   已有原生定时能力；没有时，候选路径是 GitHub Actions `schedule` 调用受维护令牌保护的
   刷新入口。GitHub Actions 的定时触发是尽力而为，可能延迟，不能作为严格 SLA。
7. 公开接口 `/api/public-report` 的读取顺序改为：
   - 先检查 60 秒 Cache API，命中则直接返回；
   - 未命中时读取对应的一个快照 key 并校验包装；
   - 快照有效时直接返回 `payload`，不再列举或读取 `h_*` 指标 key；
   - 快照缺失、损坏、版本不兼容或内容不匹配请求组合时，回退到 SPEC-0025 的动态计算。
8. 快照生成或写入失败时保留上一版本，不回滚或删除旧快照。只要旧快照仍可解析，公开接口
   继续返回旧数据；刷新失败通过日志/监控和 `generatedAt` 过旧告警发现，不因单次定时失败
   直接让看板不可用。
9. 不在 `/v1/collect` 写入路径中同步更新快照。上报请求仍只更新现有 HLL 分片，避免写放大、
   并发读改写丢更新和采集延迟扩大。
10. 保持公开响应现有字段、范围白名单、HLL 口径、隐私边界、成功/错误缓存语义和私有
    `/api/report` 行为不变。是否在公开响应中新增 `generatedAt` 字段，实施时先更新
    SPEC-0022 并完成兼容性测试。
11. 增加刷新结果的可观测性：记录成功组合、耗时、失败原因类别和快照时间，不记录令牌、
    IP、请求头或原始 HLL 内容。建议在 `generatedAt` 超过两个刷新周期加余量时告警。

## 验收标准（可测）

- [ ] **D1** 定时刷新一次会生成六份固定 key 的快照；key 名、`schemaVersion`、
      `range`、`granularity` 与 `generatedAt` 完整且可校验。
- [ ] **D2** 有效快照命中时，`/api/public-report` 最多读取一个快照 key，不列举或读取
      任何 `h_*` 指标 key，也不执行 HLL 反序列化与合并。
- [ ] **D3** 快照缺失、JSON 损坏、版本未知或 `range` / `granularity` 不匹配时，
      自动回退到现有动态计算并返回正确报表。
- [ ] **D4** 刷新入口只接受 `POST` 和六种固定范围/粒度组合；缺失或错误令牌返回
      `401` / `403`，错误响应不缓存、不泄露令牌或内部异常。
- [ ] **D5** 六次刷新可被串行编排；定时任务重叠时不会并发刷新同一快照，单次刷新失败
      不影响其余组合。
- [ ] **D6** 新快照生成或写入失败后，旧的最后成功快照仍可返回；公开接口不会因刷新任务
      单次失败而整体返回 `503`。
- [ ] **D7** `/v1/collect` 的 KV 写入 key、写入次数和请求延迟不因快照功能增加；
      采集路径不会主动生成或更新公开快照。
- [ ] **D8** 快照命中的响应与同一时刻动态计算响应在字段、数值、近似元数据和缓存头方面
      等价；60 秒 Cache API 仍只保存成功的 200 响应。
- [ ] **D9** 定时任务及刷新日志不包含令牌、IP、请求头或原始 HLL；快照过旧可仅凭
      `generatedAt` 和监控指标识别。
- [ ] **D10** SPEC-0022、SPEC-0025、统计服务 README、架构说明和测试同时更新；
      部署与线上验收另行取得明确授权。

## 非目标 / 边界

- 本 SPEC 当前不创建定时任务、不新增 KV key、不修改 Edge Function、不部署。
- 不把公开接口扩展为任意日期范围，也不替代维护者 `/api/report` 的 JSON/CSV 能力。
- 不修改 HLL 参数、分片数量、现有 `h_*` key 布局或客户端上报协议。
- 不追求实时看板；刷新周期、KV 最终一致与公开缓存会形成累计延迟。
- 不引入数据库、消息队列、常驻服务或多区域复制。
- 不在每次上报时重算快照，也不允许匿名公开请求触发快照刷新。
- 不预先创建 ADR；只有真正决定实施并涉及长期架构取舍时再记录决策。

## 设计要点（可选）

- 快照生成复用现有动态报表代码，避免维护两套 M1～M8 聚合逻辑。刷新入口只负责校验、
  调用同一构建函数并写入包装，公开快照读取入口只负责读取和校验缓存结果。
- 每个快照独立写入，不做六份快照的全有或全无提交。不同组合允许有几秒到几分钟的
  `generatedAt` 差异；看板展示的是聚合趋势，不要求六份响应来自同一瞬间。
- 刷新失败时不对旧 key 做删除或覆盖。KV 单 key 写入成功后，读端最多再受 60 秒最终一致
  与 60 秒 Cache API 影响；监控和页面新鲜度文案需要如实说明这段延迟。
- 动态计算继续保留为冷启动、首次上线、快照损坏和刷新未完成时的兼容路径，因此可以逐步
  启用快照而不要求一次性迁移历史数据。
- 定时编排使用互斥/串行策略，例如 GitHub Actions `concurrency` 配合单次只刷新一个组合；
  同一时刻不叠加多个 90 天快照构建。若 EdgeOne 后续提供原生调度，优先评估原生能力，
  再决定是否迁移。

### 重新评估触发条件

当前不实施。出现以下任一情况时再评估排期和成本收益：

- 稀疏期过后，7 天公开请求的典型 KV `get` 达到几十次，或 90 天达到数百次；
- SPEC-0025 部署后，在 Cache API 行为正常的前提下，公开接口 p95 TTFB 仍明显回升，
  例如超过约 1 秒；
- 看板访问量增加，导致冷缓存请求频繁重复执行相同聚合；
- 维护成本已能覆盖定时任务、令牌轮换、失败告警和快照新鲜度监控。
