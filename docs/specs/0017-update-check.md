# SPEC-0017：更新检查

- 状态：in-progress
- 日期：2026-11-02
- 关联：ADR-0018 · SPEC-0015 · SPEC-0010 · SPEC-0014

## 背景 / 问题

当前应用没有更新提示。用户只能自行访问 GitHub Releases 判断是否有新版本；便携版和
NSIS 安装版都没有统一的「当前版本 / 检查更新」入口。旧版 Electron 应用曾使用
electron-updater 检查更新，但新版尚未接入；直接做应用内自动安装又会引入签名密钥、
发布产物和便携版替换等问题。

## 需求（做什么）

1. 设置窗口 `System` 页签提供 `Updates` 卡片，显示当前版本和「检查更新」按钮。
2. 检查结果分为：检查中、已是最新、发现新版本、检查失败、暂无发布版本。
   只有成功解析 GitHub 响应时才显示「已是最新」；网络、限流或响应异常必须显示失败。
3. 应用启动后默认自动检查更新，延迟约 30 秒执行；之后每 24 小时最多自动检查一次。
   设置中提供「自动检查更新」开关，默认开启；关闭后不再后台请求，但手动检查仍可用。
4. 开发构建不执行自动检查；手动检查仍可用于调试。
5. 更新源为 GitHub Releases API：
   `https://api.github.com/repos/githunhunhub/breaktimer-new/releases/latest`。
   只接受 `vMAJOR.MINOR.PATCH` 形式的稳定版本；按数字逐段比较，当前版本不低于最新版本时
   视为已是最新。
6. 发现新版本时显示版本号、发布时间和下载入口。下载入口按「百度网盘、夸克网盘」排序；
   不显示 GitHub Releases 下载入口，GitHub 仅用于版本检查。网盘链接由发布元数据提供，
   未配置时显示下载链接未配置提示。
   所有入口都在系统浏览器中打开，应用不下载、不执行、不安装任何文件。
7. 同一版本在一次安装中只自动通知一次；通知不得依赖「点击通知」行为。自动通知在休息进行中
   应延迟到休息结束后发送。
8. 便携版不自我替换。更新卡片提供明确的更新步骤：退出应用、下载新便携 ZIP、解压并覆盖
   程序文件、保留 `data\` 目录、重新启动。
9. 安装版只提供下载入口；用户下载 NSIS 安装包后自行覆盖安装，设置保留。应用内不做安装。
10. 设置字段 `checkForUpdates: boolean` 默认 `true`；旧设置缺少该字段时按默认值加载。
    自动检查时间与已通知版本作为运行元数据持久化，不新增独立设置文件。
11. 新增文案全部进入 `app/locales/en-US.json` 与 `app/locales/zh-CN.json`，包括设置页、
    状态文本、便携版步骤、按钮、错误提示和系统通知。
12. 更新检查只向 GitHub 请求公开 Release 信息，不发送设备标识或使用数据；打开的下载 URL
    必须使用 HTTPS 且主机限定为夸克网盘、百度网盘。
13. 发布侧维护 `.github/release-downloads.json`（可选），发布流水线把它转换成可见的
    「下载方式」段落和隐藏的机器可读标记；应用从 Release 正文读取该标记。文件缺失或链接为空时
    应用显示下载链接未配置提示，不阻塞发布。当前先用空值占位，具体夸克 / 百度链接后续填入。
14. 不新增托盘入口；更新入口只在设置页和自动通知中出现。

- [ ] **U5** 断网、GitHub 限流、超时或响应异常时显示「无法检查更新」，不得显示「已是最新」。

- [ ] **U7** 自动检查在启动约 30 秒后触发；距离上次自动检查不足 24 小时时不重复触发。
- [ ] **U8** 开发构建不自动检查。
- [ ] **U9** 同一新版本在一次安装中只自动通知一次；重启后不重复通知同一版本。
- [ ] **U10** 休息进行中发现新版本时，通知延迟到本次休息结束后发送。

- [ ] **U13** 所有新增文案在中英文下完整、无缺失 key；通知文案使用当前有效语言。
- [ ] **U14** 版本比较覆盖相等、升级、降级、`v` 前缀、非法版本、多位数字比较等用例。
- [ ] **U15** 应用不会自动下载、执行或安装更新文件；所有下载入口只打开 HTTPS 允许列表中的 URL。
- [ ] **U16** 发布配置提供网盘链接时，Release 正文包含可见「下载方式」段落与隐藏标记；
      配置缺失时发布仍成功，应用显示下载链接未配置提示。
- [ ] **U17** 设置页之外没有新增托盘菜单项；现有托盘菜单行为不变。

## 非目标 / 边界

- 不接入 `tauri-plugin-updater`，不做应用内下载、静默安装、自动重启或回滚。
- 不做便携版自我替换或后台替换器。
- 不新增托盘「检查更新」入口。
- 不镜像 Release 到 Gitee，不增加国内更新服务器；GitHub 不可达时只提示失败和手动入口。
- 不检查 prerelease、nightly 或自定义更新通道。
- 更新检查本身不上报遥测、设备标识或使用统计；装机统计是独立需求，见 SPEC-0018。
- 不修改现有发布产物清单（NSIS、便携 ZIP、SHA256SUMS）；网盘链接只作为 Release 正文元数据。
- macOS / Linux 不在本轮验收范围。

## 设计要点（可选）

- 后端新增 `app/src-tauri/src/updates/`：版本比较、Release JSON 解析、下载元数据解析、
  GitHub 请求与自动检查调度。纯解析逻辑与 HTTP 分离，测试不访问网络。
- 手动检查通过 Tauri command 返回类型化结果；自动检查使用后台线程 / 异步任务，完成后发送
  `update-status` 事件并触发设置页刷新（不新增托盘项）。
- 自动检查元数据写入现有 `settings.json` 的 StoreData：`updateLastCheckedAt`、
  `updateLastNotifiedVersion`；不新增文件。
- 设置模型增加 `checkForUpdates`，默认 `true`；设置页 `System` 页签新增 `Updates` 卡片。
- `AppInfo` 增加 `portable` 标记，供卡片选择安装版 / 便携版文案。
- 下载入口由后端返回经允许列表校验的 URL；前端只调用打开命令，不拼接任意 URL。
- 发布元数据标记格式（Release 正文）：
  `<!-- breaktimer-downloads {"baidu":"https://...","quark":"https://...","baiduCode":"..."} -->`
- 便携版更新步骤（用户可见文案基准）：
  1. 从下面任一方式下载新版本便携 ZIP。
  2. 在托盘菜单选择「退出」，完全关闭 BreakTimer-new。
  3. 解压 ZIP 到临时目录，将 `BreakTimer-new` 文件夹中的 `breaktimer-new.exe`、
     `README.txt`、`portable.flag` 复制到当前程序目录，覆盖旧文件。
  4. 不要删除或覆盖 `data\` 文件夹；设置和运行数据保存在那里。
  5. 重新运行 `breaktimer-new.exe`。
- 自动检查与通知使用 Rust 侧 i18n 资源；前端卡片使用 React i18n，同一 key 语义保持一致。
