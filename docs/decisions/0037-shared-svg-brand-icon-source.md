# ADR-0037：应用与网站共享 SVG 品牌图标源

- 状态：已接受
- 日期：2026-11-19
- 决策者：项目维护者

## 背景

应用托盘、窗口、安装包、宣传页和 README 各自引用不同副本的旧品牌位图。用户指定
`breaktimer-app/resources/src/icon.svg` 中的图形作为统一对外 logo，而旧源码目录必须保持只读。
各消费平台接受的格式并不相同：Web 页面可以直接使用 SVG，Windows 托盘、安装包与社交分享
预览仍需要 PNG 或 ICO。

## 决策

1. 将指定 SVG 文件原样复制到新版 `app/assets/logo.svg`，作为应用与网站的唯一品牌图形源。
2. 网站可见 logo、favicon 与 README 展示图直接引用 `logo.svg`；Apple touch icon、OG 分享图、
   Tauri bundle PNG 与托盘 PNG 由同一 SVG 导出并保持既有文件名和尺寸。`icon.ico` / `icon.icns`
   在已有资源容器内替换图标图像，保留其多尺寸与格式兼容性，不改动 Tauri 对上述文件的引用。
3. 不修改 `breaktimer-app/` 中的指定文件，也不改变 Tauri 当前按文件名消费图标的机制。
4. 图标生成产物纳入版本库，跨设备无需额外安装图形转换工具即可运行和构建。

## 理由

保留单一 SVG 源可以避免多处手工重绘造成视觉漂移；直接引用 SVG 的 Web 场景能保持清晰缩放，
为兼容性保留派生位图则可以覆盖 Windows、favicon 和社交预览的实际限制。沿用既有文件名与尺寸
把改动控制在资产内容层面，不牵动 Tauri 配置、托盘代码或发布脚本；直接改写 ICO / ICNS 内的
图像项可保留现有多尺寸容器，不需要引入额外的二进制图标工具链。

## 影响

- 部分取代 SPEC-0016 Q5 中旧位图作为站点图标来源的结论；宣传页其他纯静态与本地资源约束不变。
- 品牌图形变化时需要更新 `app/assets/logo.svg` 并按站点说明重新生成所有派生位图。
- 本决策不包含打包操作；发布包中的图标会在后续正常发布流程中由现有构建链消费。
