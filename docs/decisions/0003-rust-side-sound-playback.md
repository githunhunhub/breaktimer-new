# ADR-0003：声音由 Rust 侧播放

- 状态：已接受
- 日期：2026-10-14
- 决策者：项目作者

## 背景

SPEC-0009 要求休息开始和结束时播放提示音。旧版 Electron 使用一个隐藏的
sounds 窗口和 Howler 播放 WAV 资源；新版休息窗口按软遮挡要求不抢焦点，
WebView 中的自动播放可能被浏览器策略拦截，隐藏窗口也会增加一条独立生命周期。

## 决策

声音播放放在 Rust 后端的 `sounds` 模块中，使用 `rodio` 解码并播放随应用打包的
WAV 资源。调度层在休息开始/结束状态转换时调用播放函数；`SoundType::None`
直接跳过，音量限制在 0–1。

## 理由

- 不受 WebView 自动播放策略和窗口焦点状态影响。
- 休息开始、自然结束、手动结束都由后端统一触发，不会出现多显示器重复播放。
- 声音资源和播放逻辑随桌面端打包，不依赖隐藏窗口是否已加载。

## 备选方案与取舍

| 方案 | 结论 |
| --- | --- |
| 前端 `HTMLAudioElement` | 实现简单，但无焦点窗口下自动播放不可靠。 |
| 隐藏 sounds 窗口 + Howler | 最接近旧版，但引入额外 WebView 和生命周期管理。 |
| Rust `rodio` | 增加一个音频依赖，但播放通道稳定、后端触发点集中，因此采用。 |

## 影响与风险

- 首次播放时会打开系统默认音频输出设备；设备不可用时记录错误并继续运行，
  不阻断休息调度。
- 播放放在独立线程中，避免阻塞 1 秒调度循环。
- WAV 资源从旧版只读仓库复制到 `app/src-tauri/sounds/`，后续打包无需依赖旧仓库。
