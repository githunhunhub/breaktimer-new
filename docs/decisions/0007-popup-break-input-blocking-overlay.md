# ADR-0007：Popup 休息阶段使用可聚焦的输入阻断覆盖层

- 状态：已接受
- 日期：2026-10-19
- 决策者：项目作者

## 背景

M4 阶段 4 人工验收时确认，Popup 休息窗原先沿用了旧版的「软遮挡」语义：
窗口不抢焦点，用户仍可操作底层应用和系统托盘。项目作者随后明确新的验收语义：

- 休息开始后，每个显示器都必须被休息窗完整覆盖，包括 Windows 任务栏和托盘区域；
- 底层应用、任务栏和托盘在休息期间不能接收鼠标输入；
- 应用层唯一可用的退出操作是休息窗中的 `Cancel Break`；
- 仍不要求实现 kiosk 级硬锁定，Alt+Tab、Windows 键等系统级切换不在本阶段范围。

ADR-0004 中「铺满显示器 bounds、不调用原生全屏」的几何方案仍然适用，但其中
`focusable:false` 与 `showBackdrop=false` 居中小窗的语义不再适用于激活休息阶段。

## 决策

继续使用「窗口位置与尺寸 = 显示器 bounds」的方式覆盖每个显示器，不使用原生全屏。
窗口交互按阶段区分：

| 阶段 | 窗口尺寸 | 焦点策略 |
| --- | --- | --- |
| 休息前提示条 | 显示器顶部窄条 | 不可聚焦，不打断当前应用 |
| 激活 Popup 休息 | 完整显示器 bounds | 可聚焦，显示时主动获得焦点 |

激活 Popup 休息时：

1. 每个显示器的窗口都保持无边框、透明、置顶、跨工作区和跳过任务栏；
2. 至少一个覆盖窗获得键盘焦点，其他覆盖窗仍处于置顶输入阻断层；
3. `showBackdrop` 只控制视觉遮罩强度，不再控制窗口几何：
   - `true`：显示半透明遮罩；
   - `false`：覆盖窗仍然铺满显示器，但视觉上只显示居中的休息卡。
4. 自然结束或 `Cancel Break` 后关闭所有覆盖窗。

本 ADR 部分取代 ADR-0004 中针对激活休息阶段的 `focusable:false` 与
`showBackdrop=false` 居中小窗表述；ADR-0004 的显示器 bounds 几何方案继续有效。

## 理由

- 满足用户确认的核心体验：休息时不能继续点击底层应用、任务栏或托盘。
- 不切换到原生全屏 Space，避免 macOS 全屏空间切换和多显示器行为差异。
- 透明全屏输入阻断层可以在「不显示强遮罩」时保留桌面可见性，同时仍阻止误操作。
- 保留系统级快捷键逃生路径，不把产品升级为不可恢复的 kiosk。

## 影响与风险

- 激活休息期间无法再通过托盘执行 `Disable`、`Quit` 或 `Start break now`；验收流程
  必须先点击 `Cancel Break` 结束休息，再操作托盘。
- Windows 上需要确认置顶且获得焦点的覆盖窗确实盖住任务栏和托盘；若窗口管理器
  仍把系统 UI 放在更高层，需要在平台层补测试和实现。
- macOS/Linux 的可聚焦置顶窗口行为需在对应平台验收，不在本次 Windows 修复中
  宣称已通过。
- Alt+Tab、Windows 键、任务管理器等系统级能力仍可切换或关闭应用，这是明确的
  非目标，不属于本 ADR 承诺的阻断范围。
