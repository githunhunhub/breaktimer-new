# ADR-0016：AI 记忆分级与文档单一事实源

- 状态：已接受
- 日期：2026-11-02
- 决策者：项目作者

## 背景

`AGENTS.md` 的文档工作流要求「会话结束更新 `.ai/memory.md`」，实践结果是 memory 变成按时间
堆叠的流水账（83 行、约 1.5 万字节），与 `.ai/sessions/`、`roadmap.md`、`architecture.md` 大量
重复。新会话必须读完一屏历史才能接续，且容易读到过期结论。

同时，命令与索引在多个文件里各写一份，已经产生漂移：`AGENTS.md` 的后端命令路径只在仓库根成立、
`docs/plans/README.md` 漏掉了 PLAN-0004、`docs/architecture.md` 仍标着「SPEC-0014，待实现」。

## 决策

- `.ai/memory.md` 只做**索引**，固定四节：当前状态、不变量与坑、未决事项、入口链接，控制在一屏内。
- 过程细节、验收清单、测试计数、产物哈希只写 `.ai/sessions/*`，memory 只引用不复制。
- 命令的完整来源是 `DEVELOPMENT.md`；`AGENTS.md` 只保留「完成定义」门禁清单，不再重复全部命令表。
- 索引表（`docs/specs/README.md`、`docs/plans/README.md`）的内容与状态必须在同一提交内同步。
- 文档与实现冲突时，以实现为准，并在同一次提交里先修文档。

## 理由

- 上下文窗口是新会话最稀缺的资源；索引化后接续成本固定，不随会话数线性增长。
- 单一事实源消除「同一个命令几种写法」这类漂移，也避免 AI 依据过期文档做判断。
- 过程留在 sessions 并不丢信息：原文仍在会话文件与 Git 历史里，需要时可检索。

## 影响

- 每次会话结束只更新 memory 的四节，不再追加流水条目。
- 新增 spec / plan / ADR 时同步索引，属于完成定义的一部分。
- 一次性验收清单不再单建 `.ai/checklists/`，随会话记录归档；历史清单由 Git 历史保留。
