# ADR-0028：休息卡形状从下一次休息生效

- 状态：已接受
- 日期：2026-11-13
- 决策者：项目作者
- 关联：SPEC-0021 · SPEC-0002 · SPEC-0010 · SPEC-0014 · ADR-0007 · ADR-0027

## 背景

ADR-0027 在形状设置之外引入了 `settings-changed` 广播，让已经打开的休息窗即时替换
settings 快照。复核 SPEC-0021 与 ADR-0007 后发现，这个额外机制既不是需求验收项，也与
激活 Popup 休息阶段的应用层输入阻断相冲突：用户此时无法进入设置窗保存形状，而现有
`locale-changed` 已经承担语言保存后的即时刷新。把完整 Settings 再广播给所有休息窗，
还增加了「保存任意设置都可能改变当前休息窗表现」的隐患。

## 决策

部分取代 ADR-0027 中「保存设置后广播 `settings-changed`，已打开休息窗即时读取新形状」
的决策；ADR-0027 关于形状枚举、默认值、旧配置回退、渲染组件拆分和设置文案的结论继续有效。

1. 不以事件即时刷新形状或完整 settings 快照。保存形状只写入现有设置模型；休息窗在
   创建或进入下一次休息时通过既有 `get_settings` 读取配置，形状从下一次休息生效。
2. 不新增 `settings-changed` 事件，不改动 `set_settings` 的现有 `break-status` 与
   `locale-changed` 广播；语言即时切换仍按 SPEC-0014 / ADR-0012 的既有事件执行。
3. 矩形分支维持原有 DOM、尺寸、横向进度条、按钮与错误提示样式；只有圆形分支使用
   环形进度和圆内专用排版。

## 理由

- SPEC-0021 的边界是「只改变休息卡渲染，不改变覆盖窗几何、焦点策略与输入阻断」；
  激活休息期间设置入口本就被输入阻断层覆盖，承诺即时形状刷新没有可操作的常规路径。
- 既有设置加载流程已经具备持久化和重启后生效能力；语言之外再引入一个完整 Settings
  事件没有对应验收项，反而可能绕过 SPEC-0010 对保存副作用的约束。
- 少一个跨 WebView 事件、少一份 settings 快照，能让默认矩形路径与现有实现保持一致，
  降低回归风险。

## 影响

- 用户在休息结束后保存形状，下一次休息显示新形状；同一休息周期内不切换形状。
- 前端 `BreakClient` 不再有可选设置事件订阅，Rust `flow` / `commands` 与前端 `ipc`
  不新增事件常量；`locale-changed` 与 `break-status` 保持不变。
- SPEC-0021 的人工验收步骤改为验证「下一次休息生效」；无需验证当前休息窗即时变形。
- Windows 不同 DPI、窄屏、多显示器与中英文长文案的视觉效果仍需人工验收后才能把
  SPEC-0021 标记为 done。
