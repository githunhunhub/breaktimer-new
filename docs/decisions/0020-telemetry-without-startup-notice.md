# ADR-0020：装机统计不发送启动告知通知

- 状态：accepted
- 日期：2026-11-02
- 关联：SPEC-0018 · ADR-0019
- 部分取代：ADR-0019 第 4 条中的「首次启动做一次非阻塞告知」

## 背景

ADR-0019 决定默认开启装机统计，并在首次启动时发一条非阻塞系统通知告知用户。
实际评审时用户认为这条通知打扰，要求去掉。需要确认：去掉通知后，告知是否仍然充分，
以及披露应该放在哪里。

## 决策

1. 取消统计相关的启动通知与弹窗；应用启动时不因统计产生任何系统通知。
2. 披露集中在两处：设置页 `System` 页签的「帮助改进 BreakTimer-new」卡片（说明采集
   哪些字段、用途、如何关闭），以及 `README.md` 的「隐私与匿名统计」段落。
3. 卡片常驻显示，不折叠、不隐藏；开关关闭后立即停止请求。
4. ADR-0019 的其余约束不变：字段白名单、不落 IP、明细 180 天、默认开启、可关闭、
   端点由构建期变量注入。

## 理由

- 应用的核心通知是休息提醒；再叠加一条非功能性通知会稀释提醒的重要性，也容易被误认为广告。
- 首启通知是一次性的，用户当时忽略后仍然只能回到设置页；告知的实际承载点一直是卡片与文档。
- 去掉通知不改变采集内容与关闭能力，不放大数据风险；代价是用户不主动打开设置时不会看到披露。

## 影响

- 首次运行不再主动告知；需要更强告知时，可改为「首次启动打开设置页」或恢复通知，
  但都要新增 ADR。
- `StoreData` 不再需要 `telemetryNoticeShown` 字段；旧设置文件中的该字段会被忽略，
  不影响加载。
- 设置页文案与 README 必须保持同一口径，避免出现「应用已在统计但文档没写」的情况。
