# ADR-0010：托盘菜单原地更新

- 状态：accepted
- 日期：2026-10-22
- 关联：SPEC-0006 · ADR-0006

## 背景

Windows 便携版实测中，托盘菜单打开后会在下一次倒计时分钟变化时自动关闭，
并在原菜单位置左上角留下白色残影。运行日志显示菜单关闭与
`TrayIcon::set_menu` 调用发生在同一时刻。

ADR-0006 原先选择“快照变化时整菜单重建”。该策略能保持调度状态与菜单内容同源，
但 Windows 上 `set_menu` 会解绑旧菜单、绑定新菜单并替换原生 `HMENU`；
`TrackPopupMenu` 正在显示旧 `HMENU` 时执行替换，会结束当前菜单并留下视觉残影。

## 决策

托盘菜单只在初始化时绑定一次。后续刷新沿用同一 `Menu` 与菜单项句柄：

1. 倒计时、禁用剩余时长等文本变化通过 `MenuItem::set_text` 原地更新。
2. `Enable`、`Disable...`、`Start break now` 的显隐在状态布局变化时通过
   稳定菜单的 `remove` / `insert` 原地调整，不替换托盘绑定的根菜单。
3. macOS 标题继续通过 `TrayIcon::set_title` 独立更新。
4. 自动化测试覆盖“仅倒计时变化时只更新文本，不改变菜单布局”的刷新契约；
   2026-10-22 Windows 便携版人工验收确认菜单保持打开且关闭后无白点或残留像素。

## 理由

- 根菜单句柄在应用生命周期内保持稳定，正在显示的 `TrackPopupMenu` 不再因
  每分钟刷新而被替换。
- 保留快照作为单一状态来源，只改变渲染方式，不引入第二套调度状态。
- 文本原地更新走 Tauri 的主线程封装，调用边界清晰，也能由纯布局差异测试保护。

## 影响

- 取代 ADR-0006 第 1 条中的“整菜单重建”实现方式；ADR-0006 的其余决策继续有效。
- 托盘菜单项需要由 `TrayStateStore` 持有，刷新时不能再调用 `set_menu`。
- 菜单布局变化仍可能修改原生菜单；当前已验证的 Windows 刷新路径保持正常。若后续新增场景
  表明运行中的布局修改会关闭菜单，需要进一步限定刷新时机或改用平台原生菜单实现，并新增 ADR。
