# ADR-0032：公开报表按三个实际日指标前缀列举

- 状态：已接受
- 日期：2026-11-16
- 决策者：项目作者
- 关联：SPEC-0025 · SPEC-0022 · SPEC-0018 · ADR-0023 · ADR-0029 · 部分取代 ADR-0031

## 背景

ADR-0031 假设每天的 active、version 和 new installs 三个日维度共享
`h_YYYYMMDD_` 前缀，因此计划每天只列举一次。实际 KV key 沿用了 SPEC-0018 与
ADR-0023 的固定形态：

```text
h_act_YYYYMMDD_shard
h_new_YYYYMMDD_shard
h_ver_YYYYMMDD_shard
```

`h_YYYYMMDD_` 不匹配任何日指标 key。若不修正，非空 namespace 的公开报表会把所有
日指标读成零。

## 决策

1. 部分取代 ADR-0031 第 2 条中的单日前缀设计，以及由此推导的列举数量估算。
2. 范围内每天分别列举 `h_act_YYYYMMDD_`、`h_new_YYYYMMDD_` 和
   `h_ver_YYYYMMDD_` 三个实际前缀。
3. 全局统计仍分别列举 `h_total_` 与 `h_install_ver_`。
4. 7/30/90 天公开范围最多执行 23/92/272 次有界列举；每类日前缀最多返回 16 个固定
   分片 key，单页即可完成。
5. 仍只读取列举结果中的实际 key，列举和读取并发上限保持 8；不扫描整个历史 `h_`
   namespace。
6. ADR-0031 中短期 Cache API、空 namespace 探测、只缓存 200 响应以及私有报表不变等
   其余决策继续有效。

## 理由

- 不修改现有 KV key 布局和写入路径，避免迁移线上数据。
- 每个日前缀的返回集由固定 16 分片约束，列举成本有明确上限。
- 虽然 90 天首次计算最多需要 272 次列举，仍显著少于原先 4352 次无效草图读取；60 秒
  Cache API 继续负责重复访问。
- 三个真实前缀直接对应当前 key helper，测试可以独立断言完整前缀集合。

## 影响

- 90 天首次未命中缓存的请求仍可能受 KV 列举延迟影响，需要部署后在预览或线上环境实测。
- 本修正不引入新 key、预计算快照或写入路径变更，也不改变公开响应的聚合口径。
- 若未来需要进一步压低 90 天首次请求延迟，应另行评估范围清单或预聚合快照，不在本
  ADR 中隐式改变数据模型。
