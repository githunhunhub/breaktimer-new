# ADR-0029：公开装机统计看板与只读接口分流

- 状态：已接受
- 日期：2026-11-15
- 决策者：项目作者
- 关联：SPEC-0022 · SPEC-0018 · SPEC-0016 · ADR-0023 · ADR-0024
- 部分取代：ADR-0023 第 7 条中“报表接口只通过 `MAINTENANCE_TOKEN` 访问”的限定；
  私有 `/api/report` 及其令牌鉴权继续有效

## 背景

装机统计已经通过令牌保护的 `GET /api/report` 提供 M1～M8 聚合，但手工拼装日期和鉴权头
不适合日常查看趋势。项目作者决定提供公开看板，并允许报表聚合数据公开，不要求访问者登录，
同时明确维护令牌不得出现在前端。

直接把现有 `/api/report` 改成公开接口会暴露任意 366 天范围和 CSV，匿名请求可绕过看板
反复触发大量 KV sketch 读取。把看板放入 `site/` 则会破坏宣传页“纯静态、无脚本”的约束，
并需要新增 CORS 和 GitHub Pages 脚本资产。

## 决策

1. 看板部署在统计服务自己的域名下，路径为 `/dashboard/`，静态文件随
   `server/metrics/public/` 发布；`site/` 保持独立宣传页。
2. 新增公开只读接口 `GET /api/public-report`。它不要求 Cookie、`Authorization` 或维护令牌，
   只接受固定 `range=7d|30d|90d` 与 `granularity=day|month`，返回 M1～M8 的匿名聚合。
3. 现有 `GET /api/report` 继续保留 `MAINTENANCE_TOKEN` 鉴权、任意日期范围、JSON/CSV 和
   `no-store`，作为维护者导出与临时查询接口。看板前端不读取也不发送该令牌。
4. 公开接口只输出白名单聚合字段，不返回逐装机数据、明文 `installId`、IP、请求头、
   原始事件、异常详情或环境变量。
5. 公开接口同源访问，不新增 CORS；成功响应使用 60 秒公开缓存，与 KV 的
   `eventual_60s` 一致性窗口对齐。错误响应不公开缓存。页面需说明 KV 一致性延迟与响应缓存
   可能叠加，总延迟约 2 分钟。
6. 看板只使用本地静态资源和同源 API，并启用严格 CSP、`Referrer-Policy: no-referrer`、
   禁止 iframe 与最小化权限。

## 理由

- 固定范围让公开 URL 数量有限且可缓存，避免匿名页面把维护者的 366 天查询能力当作公共扫描器。
- 公开接口与维护者接口分流后，两者可以独立演进：公开响应保持最小白名单，维护者继续保留
  CSV 与任意范围，不需要为了安全反复裁剪同一个入口。
- 同源部署消除 CORS、预检和跨域 Cookie 问题，也让前端资源与 API 的部署版本保持一致。
- 看板不进入 `site/` 后，宣传页继续满足无脚本、无远程资源、无构建器的现有不变量，
  GitHub Pages 发布链路也无需扩大。
- 公开的是不含个人信息的 HLL 聚合值；数据最小化边界不变，而透明公开统计可以增强项目可验证性。

## 影响

- 新增一个公开访问面与一个静态前端；需要持续维护 API 白名单、缓存头和页面口径说明。
- `/api/public-report` 的固定范围和 60 秒缓存会限制公开功能的即时性与查询自由度；任意范围、
  历史导出和 CSV 仍只能通过维护令牌完成。
- EdgeOne 当前全局 `Cache-Control: no-store` 需要按路由收窄，避免覆盖公开报表、看板静态资源
  或私有报表各自的缓存策略。
- 公开流量可能提高 KV 读取与边缘 CPU 消耗。第一版通过固定范围和缓存控制成本；
  若访问量明显增长，再评估 EdgeOne 缓存命中、WAF 限流或预计算快照，不在本 ADR 预设方案。
- 客户端上报协议、KV key、HLL 参数、`site/`、GitHub Pages workflow 与桌面应用均不因本决策改变。
- SPEC-0018、`docs/overview.md`、`docs/roadmap.md`、架构代码地图、SPEC 索引、
  ADR 索引与 `server/metrics/README.md` 需要同步公开看板边界。
