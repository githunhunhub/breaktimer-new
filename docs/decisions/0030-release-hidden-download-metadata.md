# ADR-0030：GitHub Release 仅保留隐藏下载元数据

- 状态：已接受
- 日期：2026-11-15
- 决策者：项目作者
- 关联：SPEC-0023 · SPEC-0015 · SPEC-0016 · SPEC-0017 · ADR-0018（部分取代其第 6 条） · ADR-0025

## 背景

GitHub Release 当前同时承载三类信息：变更日志、安装包资产和网盘下载入口。应用更新检查与
宣传页已经通过 Release 正文中的隐藏 `breaktimer-downloads` 标记读取网盘链接，因此可见的
「下载方式」段落不是功能依赖，只会让 Release 页面重复展示已由项目主页承担的下载引导。

## 决策

1. 从下一个正式版本开始，Release 正文只展示变更日志，不再展示可见网盘链接、提取码或
   「下载方式」段落。
2. 发布流水线继续追加隐藏的 `breaktimer-downloads` 标记，供应用更新检查和宣传页读取。
3. GitHub Release 继续保留安装包、便携 ZIP 与 `SHA256SUMS.txt` 资产。
4. 既有 Release 保持原样；不通过编辑历史正文、移动 Tag 或重建 Release 来回填新格式。
5. 用户下载入口统一引导到项目主页的下载区，GitHub Releases 作为版本历史与校验信息入口。

## 理由

- 隐藏标记已经满足机器读取需求，移除可见段落不会影响应用或宣传页。
- Release 页面聚焦版本变更和资产，下载引导由项目主页统一承担，职责更清晰。
- 保留同一份配置和标记格式，不需要迁移链接，也不会形成第二套下载元数据来源。
- 不改历史 Release，避免发布记录被事后改写。

## 影响

- `app/scripts/release-downloads.mjs` 只生成隐藏标记，不再生成可见 Markdown 段落。
- README 与开发文档改为引导用户从项目主页下载；宣传页与更新检查无须修改。
- 下一次正式发布时验收新正文格式；`v1.1.0` 及更早 Release 保持现状。
