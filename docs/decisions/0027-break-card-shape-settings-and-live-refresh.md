# ADR-0027：休息卡形状设置与保存后即时刷新

- 状态：已接受
- 日期：2026-11-13
- 决策者：项目作者
- 关联：SPEC-0021 · SPEC-0002 · SPEC-0010 · SPEC-0014 · ADR-0004 · ADR-0007

## 背景

SPEC-0021 要在原有矩形休息卡之外新增一个可选圆形卡、环形进度和形状设置。设计过程中有三处
架构取舍需要留痕：新形状如何持久化、老配置如何兼容、已经显示的休息窗如何响应设置保存。
窗口几何、焦点和输入阻断由 SPEC-0002 / ADR-0004 / ADR-0007 约束，本次不应重新设计。

## 决策

1. 在现有 `Settings` 模型中增加 `breakCardShape` 枚举（`RECTANGLE` / `CIRCLE`），Rust 与
   TypeScript 双份镜像，camelCase 序列化；默认值固定为 `RECTANGLE`，旧配置缺少该字段时
   沿用 `#[serde(default)]` 回退到矩形。不新增独立配置文件，也不提升 `settingsVersion`。
2. 把「激活 Popup 休息卡」渲染从 `break-window.tsx` 抽到 `active-break-card.tsx`：矩形分支
   保留原尺寸和横向进度条，圆形分支用归一化 SVG 圆环表达同一个进度值。提示条不读取形状，
   继续单独渲染为矩形；覆盖窗尺寸、焦点、输入阻断、调度与声音均不变。
3. `set_settings` 在写入配置并广播 `break-status` 后，再广播一个 `settings-changed` 事件，
   事件负载为刚保存的完整 `Settings`。已打开的休息窗订阅该事件并仅替换本地 settings 快照；
   不重启当前休息倒计时，不改 `break-status`，也不让订阅失败影响保存结果。
4. 形状选择放在设置窗「自定义」页签，靠近 Theme 卡片；文案键同步写入 `app/locales/` 的
   中英资源。不引入新的翻译注册机制或用户可调的圆盘尺寸 / 环宽参数。

## 理由

- 形状是用户偏好而非数据结构迁移：使用现有设置的缺失字段默认值即可兼容旧配置，新增迁移
  版本会增加无必要的升级面；默认矩形也避免未经确认地改变现有用户外观。
- 两个形状的进度都来自 `breakStartedAt` / `breakEndAt`。抽出渲染组件可让共用倒计时、文案、
  主题色和按钮只实现一次，矩形回归路径仍保持旧版 DOM 尺寸与横向进度行为。
- 已打开休息窗若只在下次休息读取配置，用户切换形状后无法立刻看到结果；广播完整 Settings
  复用已有 Tauri 事件机制，比轮询简单，也比让设置窗直接操作其它 WebView 更松耦合。
- 复用设置模型、locale 资源和既有覆盖窗意味着本次改动只落在表现层及一个轻量事件，符合
  SPEC-0021 的非目标边界。

## 影响

- `state/settings.rs` 的默认值、序列化和缺失字段回退需要前后端测试锁定；新字段会出现在
  设置文件与 `settings-changed` 负载中，但不属于装机统计上报字段。
- 保存任意设置都会发出 `settings-changed`，休息窗的 settings 快照随之刷新；订阅失败只记录
  错误，不影响保存。调度器状态与当前休息结束时间保持不变。
- 圆形长文案使用圆内可滚动区域，极长文本仍以滚动阅读而不是改变窗口 / 圆盘尺寸；Windows
  不同 DPI、窄屏、多显示器的视觉效果需要人工验收后才能把 SPEC-0021 标记为 done。
- 未来若形状选择影响窗口几何、焦点或输入阻断，必须另立决策并重新评估 ADR-0004 / ADR-0007，
  不能在本事件上叠加窗口控制逻辑。
