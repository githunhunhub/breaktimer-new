# ADR-0033：客户端统计收敛为 V2 日指标

- 状态：已接受
- 日期：2026-11-18
- 决策者：项目作者
- 关联：SPEC-0018 · SPEC-0022 · SPEC-0025 · SPEC-0026 · ADR-0023 · ADR-0029 · ADR-0031 · ADR-0032
- 部分取代：ADR-0023 第 3～6 条、ADR-0029 第 2 条、ADR-0031 与 ADR-0032 中依赖全局 key 和日/月六种查询的部分

## 背景

现有服务端围绕 M1～M8 保存日/月活跃、日/月版本活跃、日/月新增、累计装机与累计版本装机。
项目作者确认不需要精确日活或精确新增，也不需要累计、月粒度与版本迁移交叉口径。继续维护
八个编号指标会增加全局 key、月聚合、接口分支、看板标签和兼容成本，但不能带来当前需要的
决策信息。

本次只调整统计口径和读取路径，不重构客户端上报协议，也不更换 HLL、EdgeOne KV 或固定
分片存储。

## 决策

1. 产品与文档统一使用「客户端统计」，不再把该功能称为「装机统计」。统计单位仍是独立
   客户端实例，即一份独立数据目录和随机 `installId`。
2. V2 只输出以下日指标：
   - 日活跃客户端；
   - 日活跃版本、渠道和 OS 分布；
   - 日新增客户端；
   - 新增客户端渠道分布；
   - 7/30/90 天日趋势；
   - 平均日活、峰值日活和范围内新增客户端。
3. 日活跃继续使用 `h_act_<day>_<shard>` 单 HLL。版本、渠道和 OS 合并到
   `h_ver_<day>_<shard>` 的三维 map：

   ```json
   {
     "versions": { "0.1.2": "<HLL>" },
     "channels": { "installer": "<HLL>" },
     "os": { "windows-11": "<HLL>" }
   }
   ```

   新增客户端渠道使用 `h_newch_<firstLaunchDay>_<shard>` 的渠道 map，不再写入
   `h_new_<day>_<shard>`。
4. 删除 `h_total_*` 与 `h_install_ver_*` 的写入和读取。它们不再提供累计装机或累计版本
   指标，旧 key 保留但不迁移、不删除、不参与报表。
5. 旧 value 形如 `{"<version>": HLL}` 的裸 `h_ver` map 继续按 `versions` 读取；旧
   `h_new_*` 不读取。历史缺失的渠道或 OS 维度返回 `{}`，不伪造零值。
6. 固定 16 分片不变。心跳读取并写回 2 个 key（活跃、三维版本/渠道/OS）；安装读取并写回
   3 个 key（再加当日新增渠道 map）。首装请求仍同时写入当天活跃，客户端无需额外修改。
7. 私有 `/api/report` 保持令牌鉴权、任意日期范围与 JSON/CSV，但只输出日粒度 V2 指标，
   `granularity=month` 返回 `400`。公开 `/api/public-report` 只接受 `range=7d|30d|90d`
   和可选的 `granularity=day`，始终返回 `granularity=day`。
8. 公开接口的 Cache API 名称改为 `public-report-v2`。空 namespace 探测和只读取实际列举
   key 的优化保留，但只列举 `h_act_`、`h_ver_`、`h_newch_` 前缀。
9. 固定元数据仍为 `approximate=true`、`method=hll`、`consistency=eventual_60s`。范围汇总
   不再对活跃做跨日去重；只返回每日活跃的算术平均值、峰值，以及范围内新增客户端 HLL
   并集。
10. 客户端上报字段、上报时机和开关不变。首次安装与心跳目前是两个独立 HTTP 请求，服务端
    通过同一 `installId` 的 HLL 幂等更新完成去重。

## 理由

- 直接围绕需要展示的指标建模，可删除 32 个全局 key、月聚合分支和累计版本歧义。
- 把版本、渠道和 OS 收进同一个日 key，心跳和安装写入分别只有 2 次和 3 次读取/合并/写入，
  比原安装路径少 2 次 KV 操作。
- 裸版本 map 兼容可避免迁移历史 key；新维度从上线后逐步积累，报表明确展示未知维度为空。
- HLL 对重复 `installId` 幂等。客户端覆盖升级保留 `installId`，因此不会重复增加日活跃或
  新增客户端；跨版本升级只会让同一客户端在不同日期出现在不同版本分布中。

## 影响

- 私有报表和公开看板的字段、CSV 列、日志计数与看板模型按 V2 更新。
- 历史 `h_total_*`、`h_install_ver_*`、`h_new_*` 和旧 `h_ver` 数据仍占用 KV 空间，但后两类
  不再被读取。需要清理时必须单独评估，不能把删除作为本次迁移的隐式步骤。
- 历史日期只有版本维度，渠道与 OS 分布会显示为空；新数据上线后才开始形成完整三维分布。
- SPEC-0026 的“7/30/90 × 日/月六种快照”前提不再成立，需标记为 superseded；如未来重新
  评估公开报表预聚合，应按 V2 单一日报表重写。
