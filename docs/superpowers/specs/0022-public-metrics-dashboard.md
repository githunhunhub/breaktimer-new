# SPEC-0022：公开客户端统计看板

- 状态：in-progress
- 日期：2026-11-15
- 最近更新：2026-11-18
- 关联：SPEC-0018 · SPEC-0016 · SPEC-0025 · ADR-0023 · ADR-0029 · ADR-0031 · ADR-0032 · ADR-0033

## 背景 / 问题

统计端点需要提供一个无需登录的同源看板，公开匿名聚合数据，同时不把维护令牌放进前端。
看板继续放在 `server/metrics/public/dashboard/`，不进入纯静态宣传页 `site/`。

原看板按 M1～M8 展示日月粒度、累计装机和范围去重活跃。客户端统计 V2 已确认不需要月粒度、
累计或范围去重活跃，因此公开接口和看板同步收敛为固定日粒度：

- 平均日活、峰值日活、范围内新增客户端；
- 活跃趋势、新增趋势；
- 最新日版本、渠道、OS 分布；
- 范围内新增客户端渠道分布；
- 逐日明细。

## 需求（做什么）

1. 看板标题、说明和资源命名使用“客户端统计”，不再使用“装机统计”。
2. 公开接口 `GET /api/public-report` 只接受：
   - `range=7d|30d|90d`，默认 `30d`；
   - `granularity` 缺省或 `day`；
   - 不接受任意 `from` / `to`、`format=csv`、重复参数或未知参数；
   - `granularity=month` 返回 `400`。
3. 公开响应固定 `granularity="day"`，包含：
   - 固定元数据 `approximate=true`、`method=hll`、`consistency=eventual_60s`；
   - `range`、`from`、`to`、`generatedDay`；
   - `summary.activeAverage`、`summary.activePeak`、`summary.newClients`；
   - 逐日 `date`、`active`、`versionsActive`、`channelsActive`、`osActive`、
     `newClientsByChannel`。
4. 公开返回只含匿名聚合，不返回 `installId`、IP、请求头、原始事件、环境变量、维护令牌或
   逐客户端记录。
5. 现有私有 `GET /api/report` 保持令牌鉴权、任意日期、JSON/CSV 与 `no-store`，但同步输出
   V2 日指标；不再支持月粒度。
6. 看板范围切换只提供 7/30/90 天，不提供粒度切换。刷新按钮和加载、空数据、失败重试状态保留。
7. 看板概览只显示平均日活、峰值日活、范围内新增客户端，不显示累计、版本数量或 M 标签。
8. 看板趋势显示逐日活跃和逐日新增。逐日新增由当天各渠道估计求和；范围新增使用服务端 HLL
   并集结果。
9. 版本、渠道、OS 活跃分布展示范围内最新一天的非空数据；新增客户端渠道分布汇总范围内
   各首次启动日的渠道数据。所有分布旁必须写明口径，不把各分组相加当作总体去重活跃。
10. 逐日明细列包含日期、活跃、新增、版本、渠道、OS；所有文本在移动端可换行且不得溢出。
11. 页面说明保留：
    - 统计单位是客户端实例，不是自然人；
    - HLL 约 1～3% 相对误差；
    - KV 最终一致约 60 秒，公开缓存最多再增加 60 秒；
    - 升级保留 `installId`，不会重复增加活跃或新增；
    - 同一客户端在不同日期可以出现在不同版本分布中。
12. 页面只使用本地 HTML、CSS、JavaScript 和 SVG；不加载第三方脚本、远程字体、图片、iframe
    或统计 SDK。
13. 安全头、CSP、`Referrer-Policy: no-referrer`、禁止 iframe、无维护令牌等约束保持不变。
14. 空 namespace 仍只执行一次探测；非空时只列举 `h_act_`、`h_ver_`、`h_newch_` 三个实际
    日期前缀，只 get 列表中存在的 key，并发上限 8。
15. Cache API 名称改为 `public-report-v2`，仅缓存成功 200 响应 60 秒。日志记录
    `cache`、`emptyNamespace`、列举/读取计数、平均日活、峰值日活、新增客户端和行数。

## 非目标 / 边界

- 不公开任意 366 天范围、CSV 导出、原始 sketch 或逐客户端明细。
- 不新增账号、登录、Cookie、角色、管理界面或 CORS。
- 不做低于 60 秒刷新周期、WebSocket、实时监控或数据徽章。
- 不增加留存、漏斗、下载量入库或语言分布；版本、渠道、OS 仅输出已有白名单字段。
- 不修改客户端上报协议、上报开关、HLL 参数或固定分片数。
- 不修改 `site/`、GitHub Pages workflow、桌面应用或发布流程。
- 本次不部署、不打包、不提交。

## 设计要点

- 看板沿用现有运维型密集布局和本地 SVG 趋势图，只把信息架构收敛到 V2。视觉方向是
  “纸张质感的运营报表”，签名元素是带轻微网格底纹的单页数据面板。
- 范围按钮使用分段控件；刷新按钮保留图标化文字但不引入远程图标库。
- 版本、渠道、OS 和新增渠道分布使用四个紧凑面板，桌面两列、移动单列。
- 最新日没有某维度时显示“当前维度暂无数据”，不伪造 `0` 条目。
- 新增趋势的逐日总数可由各渠道估计相加，因为新增按 `firstLaunchDay` 归日，同一客户端
  不会在不同首次启动日重复出现；范围新增仍使用服务端 HLL 并集。
- 公开路由继续避免把维护者参数透传，公开缓存只按规范化后的 `range + day` 隔离。
