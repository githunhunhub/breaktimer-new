# SPEC-0023：GitHub Release 仅保留隐藏下载元数据

- 状态：done
- 日期：2026-11-15
- 关联：ADR-0018 · ADR-0025 · ADR-0030 · SPEC-0015 · SPEC-0016 · SPEC-0017

## 背景 / 问题

当前发布流水线会把 `.github/release-downloads.json` 转换成 GitHub Release 正文中的
可见「下载方式」段落和隐藏的 `breaktimer-downloads` 标记。应用更新检查与宣传页只依赖
隐藏标记；GitHub Release 页面重复展示网盘入口会让 Releases 更像下载页，也不再符合当前
分发定位。

## 需求（做什么）

1. 从下一个正式版本开始，GitHub Release 正文只显示 `git-cliff` 生成的变更日志，不再显示
   可见「下载方式」段落、百度网盘链接、夸克网盘链接或提取码。
2. Release 正文继续包含隐藏的 `breaktimer-downloads` 标记，保持应用更新检查和宣传页读取
   网盘链接的现有能力。
3. 发布脚本读取 `.github/release-downloads.json` 的行为不变；配置缺失或链接为空时仍不阻塞
   发布。
4. README 的下载引导改为项目主页的下载区，GitHub Releases 只用于版本历史、安装包附件与
   `SHA256SUMS.txt`。
5. 本需求只对后续 Release 生效；`v1.1.0` 及更早的既有 Release 正文不改。

## 验收标准（可测）

- [x] **H1** 发布脚本提供网盘配置时，输出正文不包含 `## 下载方式`、Markdown 网盘链接或
      可见提取码，但仍包含完整的 `<!-- breaktimer-downloads {...} -->` 标记。
- [x] **H2** 发布脚本在网盘配置为空时保持正文不变，不生成空标记。
- [x] **H3** 应用更新检查与宣传页的隐藏标记解析测试继续通过，读取的链接与提取码不变。
- [x] **H4** README、`DEVELOPMENT.md`、SPEC-0015 与 SPEC-0017 不再声称后续 Release 会显示
      可见网盘下载段落。
- [x] **H5** 既有 `v1.1.0` Release 的正文、Tag 与资产均不发生修改。
- [x] **H6** `pnpm verify` 通过。

## 非目标 / 边界

- 不改变网盘链接内容或 `.github/release-downloads.json` 格式。
- 不移除 GitHub Release 的安装包、便携 ZIP 与 `SHA256SUMS.txt` 资产。
- 不修改应用内更新检查、宣传页或历史 Release。
- 不移动或重建已发布 Tag。

## 设计要点

- GitHub Release 正文承担变更日志展示；隐藏标记只作为机器可读的下载元数据，不再承担
  可见下载入口。
- 继续复用同一份配置和标记格式，避免应用、宣传页与发布脚本出现两套链接来源。
- 当前最新 Release 作为历史记录保持原样，下一次 Tag 触发新 Workflow 时采用新格式。
